# 台本の行ごとのスタイル指定を可能にする

投稿先: https://github.com/Roohey/coeiroink-mcp
状態: 2026-09-27、赤ペン回答 `issue-1-style-01`（A / A / A）で仕様確定。同日に実装・自動テスト済み、実エンジンでも確認し、v0.10.0 でリリース。この文書を仕様の正本とし、[Issue #1](https://github.com/Roohey/coeiroink-mcp/issues/1) に本文を反映する。

## 現状

- `synthesize_script` は `話者名,セリフ` 形式の行を受け取り、各行で話者の最初のスタイルを使う。
- `speak` と `synthesize` には `styleName` によるスタイル指定がある。

## 望む動作

- 台本の行ごとにスタイル名を指定できるようにする。

## 決定した仕様

2026-09-27 の赤ペン回答 `issue-1-style-01` により、以下の3点を採用する。

### 1. 呼び出し時に形式を選ぶ（Q1: A）

- 既存の `synthesize_script` に任意引数 `scriptFormat` を追加する。
- 未指定または `"legacy"` は従来の `話者名,セリフ` 形式。最初の半角カンマだけを区切りにする。
- `"styled"` は `話者名,スタイル名,セリフ` 形式。形式の自動判定はしない。
- 形式は呼び出し全体に適用し、`styled` では各行に少なくとも2つの半角カンマを必要とする。

### 2. 空のスタイル欄は、その話者の最初のスタイル（Q2: A）

- `話者A,,こんにちは` のように、スタイル欄を空にできる。空白だけの欄も同じ扱いにする。
- この場合は選ばれた話者の `styles[0]` を使う。設定ファイルやプロフィールの `styleId` を既定値には使わない。
- 話者名とセリフは空にできない。

### 3. 最初の2つの半角カンマで分ける（Q3: A）

- `styled` では最初の2つの半角カンマ（`,`）を区切りとし、残りをすべてセリフにする。
- 各欄の前後の空白は取り除く。
- 引用符は通常の文字として扱う。CSV の引用・エスケープ処理はしない。
- 半角カンマを含む話者名・スタイル名の表現は対象外とする。

### 入力と期待結果

以下の「話者A」「げんき」は説明用の名前。実行時はエンジンに存在する名前を使う。

| scriptFormat | 入力行 | スタイル | セリフ |
| --- | --- | --- | --- |
| 未指定 / `legacy` | `話者A,げんき,こんにちは` | 話者Aの最初 | `げんき,こんにちは` |
| `styled` | `話者A,げんき,こんにちは` | `げんき` | `こんにちは` |
| `styled` | `話者A,,こんにちは` | 話者Aの最初 | `こんにちは` |
| `styled` | `話者A,げんき,はい,どうぞ` | `げんき` | `はい,どうぞ` |
| `styled` | `話者A,げんき,"こんにちは"` | `げんき` | `"こんにちは"`（引用符も残る） |
| `styled` | `話者A,こんにちは` | エラー（区切り不足） | 合成しない |

## 受け入れ条件

2026-09-27 に v0.10.0 として実装し、偽エンジンを使った自動テスト（`test/script.test.mjs`、`test/speaker-resolver.test.mjs`、`test/synthesize-script-integration.test.mjs`）で確認した。同日、実エンジン（COEIROINK v2.13.0）でも MCP 経由で確認した（行ごとの styleId と manifest、空欄が設定の styleId ではなく最初のスタイルになること、省略時・`legacy` の互換性、後ろの行の不正で出力先が作られないこと、行番号付きエラー）。

- [x] MCP の入力定義に任意引数 `scriptFormat`（`legacy` / `styled`）が表示される。
- [x] 未指定と `legacy` で従来の入力を受け付け、半角カンマを含むセリフも従来どおりになる。
- [x] `styled` で行ごとにスタイルを指定でき、上の表の結果になる。
- [x] 空または空白だけのスタイル欄は、その話者の最初のスタイルに解決される。
- [x] 空の話者名・セリフ、区切り不足、不正な形式指定を拒否する。
- [x] 話者名・スタイル名は完全一致で解決し、存在しない名前や複数該当はエラーにする。最初のスタイルが存在しない場合もエラーにする。
- [x] すべての行の解析・名前解決が成功するまで音声合成を始めない。後ろの行が不正な場合も合成呼び出しは0回になる。
- [x] 行に由来するエラーには元の台本の行番号を含める。空行や前後空白を除いた先頭が `#` のコメント行を無視しても、元の行番号を維持する。
- [x] 500行・セリフ合計50,000文字・合成音声合計200 MiB の既存上限を維持する。（行数・文字数は `styled` でもテスト済み。200 MiB は該当コードを変更しておらず、専用の自動テストはない）
- [x] 全行の成功後に結果を公開し、途中の失敗で公開先に一部の WAV や manifest だけを残さない。
- [x] manifest の各行に、実際に解決された `styleId` と `styleName` を記録する。

## 対象外

- 新しい専用ツール、入力形式の自動判定、CSV の引用・エスケープ処理。
- 辞書・文字列置換、連続再生、新しいエンジンの追加。
- GitHub へのコードの初回公開。PR に進むための公開範囲確認と初回 push は別の作業として扱う。

## 進め方

- ユーザーが仕様を判断し、Codex が提案・仕様整理を担当する。
- Claude が、この確定仕様に沿った実装と検証を担当する。
- 仕様変更が必要になった場合は、理由と選択肢を示してユーザーに判断を戻す。

## 根拠（仕様確定時点のコード）

- `src/script.ts`: 最初の半角カンマで話者名とセリフを分割する。
- `src/index.ts`: 台本の全行を事前解決し、`resolveStyle(speaker)` で最初のスタイルを選ぶ。
- `src/speaker-resolver.ts`: 省略時、完全一致、該当なし・複数該当の扱い。
