# Claude 向け: Issue #1 の実装引き継ぎ

状態: 2026-09-27、仕様確定。同日 Claude が実装・自動テストを完了し、この引き継ぎは消化済み。実エンジン（COEIROINK v2.13.0）でも確認し、v0.10.0 としてリリース。この変更は Issue #1 の PR で main に反映する。

## 目的と役割

[Issue #1](https://github.com/Roohey/coeiroink-mcp/issues/1) の台本の行ごとのスタイル指定を実装する。ユーザーは Issue → PR を一人で進める流れを学んでおり、Codex が提案・仕様整理、Claude が実装・検証を担当する方針を指定した。

仕様の正本は [確定仕様](per-line-style-draft.md)。ファイル名に draft が残っているが、赤ペン回答 `issue-1-style-01` の A / A / A を反映済み。実装前に全文を読む。回答の記録（採用記録）は、公開していない作業資料として手元に保管している。

## 手順と完了条件

1. リポジトリの `CLAUDE.md` と `HANDOFF.md`（いずれも公開していない作業メモ）を読み、作業ツリーを確認する。既存の変更・未追跡の教材や調査資料を保持し、今回の実装差分を区別できる状態にする。
2. 確定仕様の入力例と受け入れ条件を確認する。A / A / A の再確認は不要。仕様を変える必要が見つかった場合だけ、理由と選択肢を提示してユーザーに判断を戻す。
3. 解析、入力スキーマ、名前解決を変更し、テストを追加する。未指定時の互換性と、全行の事前検証を重点的に確認する。
4. 利用者向け説明と `CHANGELOG.md` の Unreleased を更新する。MCP の説明から `scriptFormat` の指定方法が分かる状態にする。
5. `npm run typecheck` と `npm test` を実行する。確定仕様の各条件をどのテスト・確認で満たしたか、未検証事項も含めて報告する。実エンジンでの確認をしていなければ、その旨を明記する。
6. Issue に対応する変更点、検証結果、残る作業をユーザーに説明する。コミットはリポジトリ規約に従いユーザーの許可を得てから行う。タグ付け・リリースは明示依頼時のみ。初回 push と PR は公開範囲確認を含む別の段階として扱う。

## 実装の入口と注意点

以下は調査済みの入口であり、実装方法そのものを固定するものではない。

- `src/script.ts`: 台本の解析、元の行番号、空行・コメント、行数・文字数制限。既定を legacy に保ち、styled の空スタイルを省略相当として表現する。
- `src/speaker-resolver.ts`: 名前の完全一致と曖昧さの検出、`resolveStyle`。空文字のスタイル名をそのまま検索させないようにする。
- `src/index.ts`: `synthesizeScriptInputSchema`、ツール説明、`parseScript` 呼び出し、全行の事前解決。`scriptFormat` は音声設定用の残余引数 `...ov` に混入させず、台本処理用として取り出す。
- 合成・公開と manifest の既存処理を活用し、解決済みのスタイルを各行の合成に使う。既存の原子的な公開処理の作り直しは不要。

## テストで示すこと

- `test/script.test.mjs`: 両形式、未指定、空スタイル、空欄の trim、区切り不足、半角カンマ入りのセリフ、引用符がそのまま残ること、元の行番号と既存上限。
- `test/speaker-resolver.test.mjs`: 最初のスタイル、完全一致、存在しない名前、複数該当、スタイルなし。
- `test/synthesize-script-integration.test.mjs`: MCP から形式指定できること、各行に選んだ styleId が渡ること、後ろの行の不正で合成が0回になること、manifest の styleId/styleName。
- 既存の合成失敗時の公開・キャンセル・サイズ上限の検証を維持する。具体的な未確認リスクがある箇所だけ追加する。
